# Change Request Follow-up Notes

**Source:** Follow-up conversation with Product Management and Client Services

**Status:** Informal notes for analysis

- Product wants the change assessed before committing to a release date.
- Client Services receives questions about event deadlines, event updates, and whether an event is still relevant. They do not want the notification channel to become a second detailed event-management system.
- The Corporate Actions team owns the authoritative event content, but the integration route into the Investor Workspace has not been confirmed.
- Product is considering whether a user should receive one notification when an event is first published and another when a material field changes. No definition of material has been agreed.
- Operations asked how to distinguish a new event from an update and how to investigate a client report that an update was not received.
- Compliance wants the event content and notification wording reviewed before any external communication is approved.
- Privacy wants the team to confirm whether this new notification type uses existing consent, a separate preference, or both.
- Mobile and Web noted that the existing notification history view assumes a small set of event fields and a single destination pattern.
- Engineering has not confirmed whether the current market-data event pipeline is suitable for corporate-action events.
